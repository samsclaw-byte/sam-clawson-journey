10 Steps to MVP

With PRD, Wireframes & Claude Integration

📋 Phase 1: Planning & Setup (Days 1-2)
1
Review PRD with Claude
Before writing any code, have Claude review the PRD for gaps, risks, and technical feasibility. Validate assumptions about scope, timeline, and user needs.
⏱️ 2-3 hours 📄 PRD Review

🤖 Claude Checkpoint

"Review this PRD. What are the top 3 risks? What's missing? Is the timeline realistic?"

Resources:

📄 PRD
2
Validate Wireframes
Share wireframes with Claude for UX feedback. Identify friction points in the user flow before building. Ensure the 3-screen flow (Login → Profile → Dashboard) is optimal.
⏱️ 1-2 hours 🎨 UX Review

🤖 Claude Checkpoint

"Review these wireframes. Where might users get stuck? What would simplify the onboarding?"

Resources:

🎨 Wireframes
3
Set Up Cloudflare Infrastructure
Create Cloudflare account. Set up Pages for hosting, D1 for database, Workers for API. Configure custom domain (trak.samsclaw.org or similar).
⏱️ 2-3 hours ☁️ Infrastructure

🤖 Claude Checkpoint

"Review my Cloudflare setup. Is this architecture scalable? Any security issues?"

🔐 Phase 2: Auth & Database (Days 3-4)
4
Configure Google OAuth
Create Google Cloud project. Enable OAuth 2.0. Configure consent screen. Get client ID and secret. Build login button on frontend.
⏱️ 3-4 hours 🔑 Authentication

🤖 Claude Checkpoint

"Review my OAuth implementation. Are tokens handled securely? Is the flow correct?"

5
Create Database Schema
Create D1 database. Set up Users and Meals tables with proper indexes. Test queries for performance. Ensure user_id isolation works correctly.
⏱️ 2-3 hours 🗄️ Database

🤖 Claude Checkpoint

"Review this SQL schema. Are the indexes optimal? Any normalization issues?"

6
Test Auth End-to-End
You should be able to: Click login → Google auth → Redirect back → See your profile → Data saved in D1. Test with 2 different Google accounts to verify isolation.
⏱️ 2-3 hours ✅ Testing

🤖 Claude Checkpoint

"Here's my auth test results. What edge cases am I missing? Any security gaps?"

🎨 Phase 3: UI Development (Days 5-7)
7
Build Frontend (Follow Wireframes)
Build login page, profile setup form, and dashboard. Match wireframes exactly. Use the color scheme, spacing, and interactions from the wireframe reference.
⏱️ 6-8 hours 💻 Frontend

🤖 Claude Checkpoint

"Review my HTML/CSS. Does it match the wireframes? Mobile responsive? Performance issues?"

Resources:

🎨 Wireframes
8
Build API & Connect to Database
Create API endpoints: POST /api/meals, GET /api/meals, etc. Connect frontend forms to backend. Implement proper error handling and validation.
⏱️ 4-6 hours ⚙️ Backend

🤖 Claude Checkpoint

"Review my API code. RESTful? Proper error handling? SQL injection protection?"

🚀 Phase 4: Launch & Beta (Days 8-10)
9
Final Review & Testing
You log meals for 2 days. Test all features. Fix bugs. Ensure mobile works perfectly. Verify data persists correctly. Performance check (<2s load time).
⏱️ 4-5 hours 🧪 QA

🤖 Claude Checkpoint

"Here's my pre-launch checklist. What am I forgetting? Any critical bugs to fix first?"

10
Invite Beta Testers
Send invites to 2-3 family members. They sign up, log meals for 7 days. You collect feedback daily. Measure: Are they logging? What's hard? What do they want?
⏱️ 1 hour setup + 7 days 👥 Beta

🤖 Claude Checkpoint

"Here's my Beta feedback. Should we pivot, persevere, or kill? What's the data telling us?"

📊 Summary

  • Total Time: 10 days (active development)
  • Claude Checkpoints: 10 (one per step)
  • Cost: ~$20-30/mo (Cloudflare free tier + Kimi)
  • Deliverable: Working app with 3-5 Beta users
  • Success: Users log meals for 7 consecutive days
💡 How to Use This: Complete each step in order. Don't skip ahead. At each Claude checkpoint, paste relevant code/docs and ask specific questions. The wireframes and PRD are your reference - don't deviate without good reason.
