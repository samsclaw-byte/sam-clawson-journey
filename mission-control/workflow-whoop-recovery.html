🔧 Current Implementation (Single User)

1

Webhook Reception

WHOOP sends lightweight webhook to whoop-webhook.samsclaw.org with event type and ID. Raw JSON saved to ~/.openclaw/whoop_data/

2

Event Processing

Webhook server detects event type (recovery.updated, sleep.updated, workout.updated) and extracts the record ID from the payload.

3

API Data Fetch

Server uses OAuth access token to call WHOOP API v2 endpoints:

GET /v2/activity/sleep/{sleepId} GET /v2/activity/workout/{workoutId} GET /v2/cycle/{cycleId} (includes recovery data)
4

Token Refresh (if needed)

If access token expired (401), server automatically refreshes using the offline scope refresh token.

5

Data Storage

Full data (recovery scores, HRV, sleep stages, workout strain) extracted and saved to Airtable WHOOP Daily table.

6

Notification

Telegram notification sent to user with key metrics (recovery score, HRV, sleep performance).

✅ Current Status: Fully operational. Webhooks receiving, API fetching working, data saving to Airtable with refresh token for seamless authentication.

Multi-User Token Management Strategy

🎯 Core Principle: Each user has their own OAuth tokens. The app never shares tokens between users and maintains strict isolation.

1. Database Schema (PostgreSQL Example)

CREATE TABLE whoop_users ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), user_id INTEGER UNIQUE NOT NULL, -- WHOOP user ID email VARCHAR(255), whoop_tokens JSONB, -- {access_token, refresh_token, expires_at} last_sync TIMESTAMP, created_at TIMESTAMP DEFAULT NOW(), updated_at TIMESTAMP DEFAULT NOW() ); CREATE TABLE whoop_webhooks ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), user_id INTEGER REFERENCES whoop_users(user_id), event_type VARCHAR(50), record_id UUID, raw_payload JSONB, processed BOOLEAN DEFAULT FALSE, created_at TIMESTAMP DEFAULT NOW() ); CREATE INDEX idx_whoop_webhooks_user ON whoop_webhooks(user_id, processed);

2. OAuth Flow for New Users

1

Initiate OAuth

User clicks "Connect WHOOP" → App generates unique state parameter with user ID encoded → Redirects to WHOOP authorization URL

2

Handle Callback

WHOOP redirects to /oauth/callback?code=XXX&state=USER_ID → Server exchanges code for tokens → Stores in database with user ID

3

Register Webhook

App subscribes to webhooks for that specific user via WHOOP API (each user needs webhook registration)

3. Token Refresh Strategy

# Pseudo-code for multi-user token refresh def refresh_all_user_tokens(): """Run every 50 minutes via cron/job queue""" # Get all users with tokens expiring in < 10 minutes users = db.query(""" SELECT user_id, whoop_tokens FROM whoop_users WHERE whoop_tokens->>'expires_at' < NOW() + INTERVAL '10 minutes' """) for user in users: try: # Refresh this user's token new_tokens = whoop_api.refresh_token( user.whoop_tokens['refresh_token'] ) # Update database db.execute(""" UPDATE whoop_users SET whoop_tokens = %s, updated_at = NOW() WHERE user_id = %s """, [new_tokens, user.user_id]) except Exception as e: log.error(f"Failed to refresh token for user {user.user_id}: {e}") # Notify user to re-authenticate if refresh fails # Schedule: Run every 50 minutes schedule.every(50).minutes.do(refresh_all_user_tokens)

4. Webhook Processing (Multi-User)

@app.route('/webhook/whoop', methods=['POST']) def handle_whoop_webhook(): data = request.json # Extract user ID from webhook whoop_user_id = data.get('user_id') # Find user in our database user = db.query( "SELECT * FROM whoop_users WHERE user_id = %s", [whoop_user_id] ).first() if not user: log.warning(f"Webhook for unknown user: {whoop_user_id}") return jsonify({'status': 'ignored'}), 200 # Queue for processing (don't block webhook response) webhook_queue.enqueue( process_whoop_webhook, user_id=whoop_user_id, event_type=data.get('type'), record_id=data.get('id'), tokens=user.whoop_tokens ) return jsonify({'status': 'queued'}), 200 def process_whoop_webhook(user_id, event_type, record_id, tokens): """Background job to process webhook""" # Fetch full data using user's tokens whoop_api = WhoopAPI(tokens) if event_type == 'recovery.updated': # Fetch cycle data (includes recovery) cycle_data = whoop_api.get_cycle(record_id) # Save to user's data store db.execute(""" INSERT INTO whoop_recovery_data (user_id, cycle_id, recovery_score, hrv, resting_hr, date) VALUES (%s, %s, %s, %s, %s, %s) """, [ user_id, cycle_data['id'], cycle_data['recovery']['score']['recovery_score'], cycle_data['recovery']['score']['hrv_rmssd_milli'], cycle_data['recovery']['score']['resting_heart_rate'], cycle_data['start'][:10] ])

5. Security Considerations

⚠️ Critical Security Requirements:
  • Encrypt tokens at rest (AES-256)
  • Never log tokens or expose in error messages
  • Use separate database credentials per environment
  • Implement row-level security (RLS) in PostgreSQL
  • Rate limit per user to prevent abuse
  • Allow users to revoke access (delete tokens)
