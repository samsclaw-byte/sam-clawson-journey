🥗 Health & Nutrition App

MVP Development Process - Step by Step

📋 Development Principles

  • One phase at a time. Don't start Phase 2 until Phase 1 is complete and tested.
  • Deploy early, deploy often. Each phase should be live and working before moving on.
  • No scope creep. If it's not in the phase checklist, it doesn't get built.
  • Test with yourself first. You are the first user. If it doesn't work for you, it won't work for others.
  • Document blockers immediately. If stuck for >2 hours, pause and reassess.
1

Foundation & Auth

Pending
⏱️ 3-4 days
  • Set up Cloudflare Pages project
    Create new project, configure build settings
  • Set up D1 database
    Create database, design schema for users and meals
  • Configure Google OAuth
    Set up Google Cloud project, configure OAuth consent screen
  • Build login page
    Simple "Sign in with Google" button
  • Test auth flow
    You should be able to log in and see your user_id

🤔 Decision Required:

Which domain? samsclaw.org or nutrition.yourdomain.com?

✅ Phase 1 Complete When:

  • You can visit a URL and see a login page
  • Clicking "Sign in with Google" authenticates you
  • Your user record exists in D1 database
  • You see a basic "Logged in as [email]" page
2

Core UI & Meal Logging

Pending
⏱️ 4-5 days
  • Copy current nutrition page UI
    Meals list, macro chart, totals - but simplified
  • Build "Add Meal" form
    Meal type dropdown, food name, estimated calories (optional)
  • Connect form to D1 database
    Save meals with user_id isolation
  • Display today's meals
    Query DB for current user, today's date
  • Basic macro calculation
    Simple pie chart (can be hardcoded estimates initially)
  • Test end-to-end
    Log a meal → see it appear → check DB

✅ Phase 2 Complete When:

  • You can log in and see your dashboard
  • You can add a meal via form
  • Meal appears in today's list immediately
  • Macro chart updates (even if estimated)
3

Multi-User & Invite

Pending
⏱️ 3-4 days
  • Verify user data isolation
    User A cannot see User B's meals
  • Build invite system
    Generate invite links, email or share via text
  • Test with 2-3 family members
    Send invites, they sign up, log some meals
  • Basic admin view (optional)
    See list of users, not their data

🤔 Decision Required:

Who are the 2-3 Beta testers? Get their commitment first.

✅ Phase 3 Complete When:

  • 2-3 family members have accounts
  • They can log meals independently
  • Your data is isolated from theirs
4

Beta Testing & Feedback

Pending
⏱️ 7 days (active testing)
  • Daily check-ins with Beta users
    Ask: Did you log meals today? What was hard?
  • Fix critical bugs
    Anything preventing meal logging
  • Collect feature requests
    Note what people ask for (but don't build yet)
  • Measure engagement
    Are people logging daily? Or dropping off?
  • Decision: Pivot, Persevere, or Kill?
    Are people actually using it? Is it valuable?

✅ Phase 4 Complete When:

  • 7 days of testing complete
  • You have data: usage, feedback, bugs
  • Decision made: Build v2 or stop
💡 Remember: The goal of the MVP is to validate that people will actually log their meals consistently. If they don't, no amount of AI or fancy features will fix that. Keep it simple, get it live, test with real users.
