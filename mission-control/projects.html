💬 Embedded Chat Interface

Allow users to chat with AI directly from dashboard pages

Concept Overview

Floating chat widget on each page (Health, Work, etc.) where users type natural language like "I drank 2 glasses of water" or "Add task: Call John tomorrow"

✓ Pros

  • No app switching (Telegram → Web)
  • Context-aware (on Health page = health context)
  • Familiar interface
  • Mobile-friendly
  • Can guide users with prompts

✗ Challenges

  • Security: Sandbox user inputs
  • Cost: Rate limiting per user
  • Permissions: User vs Admin commands
  • Auth: Verify user before processing
  • Scope: Prevent "change password" etc
🔧 Technical Approach:
WebSocket → Telegram Bot → OpenClaw → Filtered Response
Only allow: add_[habit|task|food|water], query_[data], help
Block: config_*, delete_*, system_*, admin_*

💬 Embedded Web Chat Interface

IMPORTANT: Buttons and chat are embedded in the web pages, NOT through Telegram. Users interact directly on missioncontrol.com

✅ Clarified: Web-First Interface

Chat widget floats on each Mission Control page. Users click buttons and type directly on the website. No Telegram required for basic usage. Telegram/WhatsApp are optional add-ons for mobile convenience.

🌟 Future Vision (Post v1.0)

🎯 Tiered Access Levels

Free Tier: Text input only, basic nutrition + workout logging
Plus Tier: Image upload (food photos), task logging, habits
Pro Tier: Voice input, AI expert sessions, group features

🎙️ Input Methods

  • Text: Natural language ("I ate lamb biryani")
  • Image: Photo of food → auto nutrition estimate
  • Voice: "Log workout: bench press 80kg x 10 reps"

📊 Specialized Pages

  • Resistance Training: Log weights, reps, sets, progressive overload tracking
  • Cardio: Duration, heart rate zones, strain scores
  • Habits: Streak tracking, accountability groups

👥 Group Features

  • Family Dashboard: How is everyone doing?
  • Challenges: "30-day water challenge" with group progress
  • Shared Goals: Plan family fitness objectives

🤖 AI Expert Sessions

  • Fitness Coach: Review progress, adjust programs
  • Nutritionist: Meal planning, dietary analysis
  • Productivity Expert: TAT optimization, focus techniques

⚠️ Key Risks

  • Security: User isolation failures, data leaks between accounts
  • Costs: AI API usage scales with users (need rate limits)
  • Complexity: More features = more bugs, harder maintenance
  • Support: Family/friends need help, you're the only dev
  • Lock-in: Once people depend on it, hard to change stack

🚀 Opportunities

  • Learning: Real-world auth, scaling, security experience
  • Portfolio: Impressive full-stack project to show employers
  • Community: Could open-source, build following
  • Monetization: Freemium model (Free/Plus/Pro tiers)
  • Integration: Connect family data (shared grocery lists, challenges)
  • AI Differentiation: Expert sessions (fitness coach, nutritionist)
  • Market Gap: No good "family health dashboard" exists

🏷️ Branding & Naming

Product identity and section naming conventions

💡 Why "Trak" works:
  • Short (4 letters) - easy to type, easy to remember
  • Novel spelling (K instead of CK) - distinctive, domain-available
  • Verb form: "I Trak'd my lunch" - encourages usage
  • Extensible: NutritionTrak, WorkoutTrak, etc.
  • Ages well: works for individuals, families, teams

🔍 Discovery Session Concepts

Pre-build exercises to validate assumptions

💡 Suggested Discovery Activities

1. User Journey Mapping

Map the ideal flow: Open app → Log breakfast → See summary → Log lunch... Identify friction points before building.

2. Paper Prototype Test

Sketch dashboard on paper, ask family: "Log a meal. What would you tap?" 5-minute test reveals UI issues before code.

3. Assumption Validation

List assumptions ("Users want macro charts", "Families will track together"). Ask Beta candidates which matter most to them.

4. Competitive Analysis

Document: MyFitnessPal (too complex), Cronometer (too detailed), Noom (expensive). Identify the gap our product fills.
